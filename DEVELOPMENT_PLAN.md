## 0. How to use this document

Build **module by module, in the numbered order**. Each module is a single
responsibility with its own file(s), its own tests, and an explicit
"done when" gate. **Do not start module N+1 until module N's tests pass.**

Every module below specifies:
- **File(s)** — exact paths to create
- **Responsibility** — the one thing this module does
- **Interface** — public functions/classes with signatures
- **Logging** — what must be logged, at what level
- **Error handling** — what goes to the `errors` table
- **Tests** — required test cases
- **Done when** — the gate to move on

### Non-negotiable global rules

1. **Never silently drop a job.** Every job must end in exactly one terminal
   state: `scored`, `excluded`, `pending` (uncertain), or `failed`. If code
   can drop a job without a DB row and a log line, that code is wrong.
2. **Log at every stage boundary.** Entry, exit, count in, count out.
3. **Every caught exception writes to the `errors` table** — with
   `source_file`, `function_name`, `stage`, and `error_message`. Never
   `except: pass`.
4. **No secrets in code.** All config via `.env`, validated at startup.
5. **No JD text persisted.** JD is read in-memory for scoring, then dropped.
6. **Type hints everywhere.** Pydantic for all data crossing a boundary.
7. **Incremental writes.** Commit per job, not per batch.

## Module 1 — Logging Infrastructure

**File:** `src/coldstart/logging_setup.py`

**Responsibility:** Configure logging once, for the whole app. Nothing else.

**Interface:**
```python
def setup_logging(log_dir: Path, level: str = "INFO", run_id: str | None = None) -> None
def get_logger(name: str) -> logging.Logger
def new_run_id() -> str   # short uuid, tags every log line in one pipeline run
```

**Requirements:**
- Two handlers: rotating file (`logs/coldstart.log`, 10 MB × 5 backups) and console.
- Format must include `run_id` so one pipeline run is greppable:
  `%(asctime)s | %(levelname)-8s | %(run_id)s | %(name)s:%(funcName)s:%(lineno)d | %(message)s`
- Use a `logging.Filter` to inject `run_id` into every record.
- Level from `.env` (`LOG_LEVEL`), default `INFO`.
- `DEBUG` for per-job detail, `INFO` for stage summaries, `WARNING` for
  recoverable/uncertain, `ERROR` for anything hitting the `errors` table,
  `CRITICAL` for pipeline abort.

**Tests (`tests/test_logging_setup.py`):**
- `run_id` appears in emitted records.
- File handler creates the file; log dir auto-created if missing.
- Level respected from arg.

**Done when:** `get_logger(__name__).info("x")` writes to both file and console with a run_id.


**Real-data finding (discovered after this module was first built): dropped
`EXPERIENCE_START_DATE` (a start date, with X derived at runtime as
`today − start`) in favor of `EXPERIENCE_YEARS` (a direct number).** A
start-date derivation silently assumes continuous employment — a career
break would overcount X with no way for the system to detect it, which
directly contradicts the "never silently drop/never silently wrong"
principle this whole project is built around. A direct number is exact at
entry time; the cost is it doesn't auto-increment and needs periodic manual
updating, an acceptable visible tradeoff over a silent inaccurate one. This
removed the `years_of_experience()` helper entirely (no longer needed —
X is just read directly off `Settings`) and the "single shared anchor, no
per-resume split" decision carries over unchanged to `EXPERIENCE_YEARS`.

**Validation rules (must all run at startup, before any network/LLM call):**
- `experience_years` is positive and no more than 60 (sanity).
- Every provider named in `provider_fallback_order` has a non-null API key
  (unless `llm_mode == "dev"`, where only Ollama reachability matters).
- `score_threshold_consider < score_threshold_strong`.
- `digest_time_pdt` parses as `HH:MM`.
- **If** `resume_manifest` exists, every resume file it references **exists
  and is non-empty**. **If it doesn't exist yet, this check is skipped —
  not an error.** On a fresh checkout, before Module 2.5 has ever run,
  there is no manifest yet; that's expected, not a config problem.
  Producing/refreshing `resume_manifest` and the four resume JSONs it
  points to is Module 2.5's job. `check_resumes_ready` (M2.5) is the real
  go/no-go gate and runs immediately *after* settings load in `run_poll` —
  this Settings-level check only catches a manifest that exists but has
  gone stale (e.g. a referenced file was manually deleted).
- All dirs creatable.
- On any failure: raise `ConfigError` listing **all** problems at once (not
  just the first), log `CRITICAL`, exit non-zero.

**Tests:**
- Valid `.env` loads.
- Missing API key for a provider in the fallback order → `ConfigError`.
- Unknown provider name in `provider_fallback_order` → `ConfigError`.
- `resume_manifest` absent entirely → **not** an error (deferred to M2.5).
- `resume_manifest` present but references a missing file → `ConfigError` naming the file.
- `consider >= strong` → `ConfigError`.
- `experience_years` <= 0 → `ConfigError`; > 60 → `ConfigError`; fractional
  values like `3.5` accepted.
- Multiple simultaneous failures are all reported.

**Done when:** a deliberately broken `.env` produces one readable error listing every problem.

## Module 2.5 — Resume Ingestion

**File:** `src/coldstart/resume_ingest.py`

**Responsibility:** Guarantee a complete, normalized set of 4 resumes (one
per `ResumeId` slot A/B/C/D) exists before anything downstream can run.
Converts raw PDF/DOCX into normalized JSON; **hard-stops the application**
if the resume set can't be resolved. Runs at the start of every
`run_poll` invocation (per scope.md §5.1) — cheap no-op on the common case
where nothing changed.

**Interface:**
```python

    source_sha256: str

    full_text: str

    # raises ExtractionError (corrupt file, encrypted PDF, image-only/no text layer)

    # deterministic keyword match, same is_fde/is_ai signal convention as M11's
    # route_by_keywords, applied to the filename stem instead of a job title

def classify_slot_from_content(text: str, chain: list[LLMProvider]) -> ResumeId
    # LLM fallback, called ONLY when the filename doesn't resolve unambiguously.
    # Strict enum output, Pydantic-validated, one correction retry (same pattern as M11/M15).

def ingest_resumes(resumes_dir: Path, manifest_path: Path, chain: list[LLMProvider], conn) -> dict[ResumeId, NormalizedResume]
    # full flow: scan -> hash-check -> extract -> classify -> validate 1:1 coverage
    # of all 4 slots -> write resume_<slot>.json -> archive original -> regenerate manifest.json

def check_resumes_ready(resumes_dir: Path, manifest_path: Path) -> bool
    # cheap fast-path: do 4 valid, non-empty slot JSONs already exist with no
    # new/changed source files sitting in resumes_dir? If yes, return True (no-op).
    # If no, caller must invoke ingest_resumes (or raise ResumesNotReady if that
    # also can't resolve it).
```

**Logic:**
1. Scan `config/resumes/` (top level only, not `originals/`) for `*.pdf` /
   `*.docx`, case-insensitive.
2. **Idempotent fast path:** if all 4 `resume_<slot>.json` files exist, are
   non-empty, and their recorded `source_sha256` matches every source file
   currently in the directory → return immediately. No extraction, no LLM
   call. Mirrors the manifest-slice sha256 pattern from M5 — this is the
   expected outcome on nearly every run.
3. **Hard stop — nothing to work with:** zero source files found **and**
   fewer than 4 valid slot JSONs exist → raise `ResumesNotReady` naming
   every missing slot, e.g. *"No resumes found in config/resumes/. Add 4
   resumes (PDF or DOCX) — one each for: general SWE, AI/Agentic Engineer,
   FDE (general), FDE (AI) — then re-run."* Logged `CRITICAL`. The caller
   (`run_poll` / `scripts/ingest_resumes.py`) prints this and exits
   non-zero. **The pipeline must never run with an incomplete resume set** —
   this is as hard a gate as Module 2's config validation.
4. For each new/changed source file:
   a. `extract_text` — deterministic, no LLM. On failure (corrupt file,
      encrypted PDF, or a scanned/image-only PDF with no text layer — pypdf
      does **not** OCR) → `log_error(stage="resume_ingest")`, then hard
      stop naming the file. Unlike a bad *job* row, a bad *resume* blocks
      the whole run — there's no "uncertain" bucket that lets scoring
      proceed on 3 of 4 slots.
   b. `classify_slot_from_filename` first (free). Recognized markers, same
      spirit as M11: stem contains `fde` → `is_fde=True`; stem contains
      `ai`/`agentic`/`ml` → `is_ai=True`. Resolves the slot deterministically
      when unambiguous.
   c. If the filename doesn't resolve → `classify_slot_from_content`, one
      LLM call, logged `WARNING` (worth eyeballing since it's the fallback
      path). If that also fails to validate after one retry → hard stop,
      naming the file, asking the user to rename it per the documented
      convention rather than guessing at a high-stakes classification.
5. **Coverage check** after processing all files: exactly one resume must
   map to each of A/B/C/D.
   - Two files resolve to the same slot → hard stop, name both filenames.
   - A slot with zero resolved resumes → hard stop, name the missing slot.
6. Write `config/resumes/resume_<slot>.json` (`NormalizedResume.model_dump_json(indent=2)`).
7. Move the original into `config/resumes/originals/` (create if missing) —
   **archived, never deleted**, so re-running is safe and the user's source
   file isn't lost.
8. Regenerate `config/resumes/manifest.json` from the 4 `NormalizedResume`
   records (`id -> {file, description}`). No per-resume experience field —
   X (`EXPERIENCE_YEARS`) is read directly off `Settings` at scoring time,
   not stored in the manifest (confirmed decision: all 4 resumes share one
   YOE anchor, no per-resume split).

**Format decision — JSON, not YAML:** every other config file in this repo
(`manifest.json`, `title_rules.json`, `eligibility_rules.json`,
`excluded_ats.json`, `us_states.json`) is already JSON, and Pydantic v2
round-trips it with zero extra dependency (`model_dump_json` /
`model_validate_json`). YAML would add a dependency and its whitespace/type-
coercion footguns for no benefit here, since this file is machine-written
and machine-read, not hand-authored.

**Normalization depth — flat text + metadata, not fully structured
sections.** `full_text` is what Module 14's `build_system_prompt` already
expects (`resume_text: str`); no other module needs to change. If resume
auto-tailoring (scope.md §13, future extension) is ever built, it can layer
structured extraction on top of `full_text` later without redoing this module.

**Privacy:** `config/resumes/*.json`, `config/resumes/originals/`, and any
raw `*.pdf`/`*.docx` sitting in `config/resumes/` contain full resume text
(PII) and must be added to `.gitignore` alongside `.env` — never committed.
Only `manifest.json`'s *shape* is safe to reason about; it is regenerated,
not hand-edited, so it's fine to gitignore too for simplicity.

**Logging:** `INFO` per file: filename → resolved slot, method
(`filename`/`llm`). `INFO` summary: `"4/4 resume slots resolved"` or
`"resumes unchanged, skipping ingestion"`. `WARNING` on every LLM-fallback
classification. `CRITICAL` + hard stop on: no resumes found, extraction
failure, unresolved slot ambiguity, missing slot coverage.

**Error handling:** every hard-stop path still writes to the `errors` table
(`stage="resume_ingest"`) for the audit trail, but — unlike job-processing
errors — these abort the run rather than being logged-and-continued.

**Tests (`tests/test_resume_ingest.py`):**
- Empty `config/resumes/` (no source, no JSON) → `ResumesNotReady`, message
  names all 4 missing slots.
- One `.pdf` + one `.docx` with unambiguous filenames → both extracted,
  correctly slotted, JSON written, originals moved to `originals/`.
- Ambiguous filename (e.g. `resume.pdf`) → LLM fallback invoked (assert
  called with a `FakeProvider`), slot assigned from the mocked response.
- LLM fallback also invalid after retry → hard stop naming the file.
- Two files both resolve to slot B → hard stop naming both filenames.
- Only 3 of 4 slots covered → hard stop naming the missing slot.
- Re-run with no source-file changes and all 4 JSONs present → zero
  extraction calls, zero LLM calls (fast no-op path) — assert on call counts.
- Source file changes (new sha256, same filename) → re-extracted, JSON
  updated, archived original overwritten.
- Corrupt/unreadable PDF → hard stop, error row logged with the filename.
- Scanned/image-only PDF (no text layer) → treated as an extraction
  failure, not silently accepted as an empty resume.

**Done when:** dropping a mixed PDF/DOCX pair with unambiguous filenames
into `config/resumes/` and running `scripts/ingest_resumes.py` produces 4
valid slot JSONs, a regenerated `manifest.json`, and archived originals; a
second consecutive run performs zero extraction and zero LLM calls.

**File:** `src/coldstart/manifest_watch.py`

**Responsibility:** Decide *which slices changed*. Downloads nothing.

**Interface:**
```python

    ats_type: str; parquet_url: str; sha256: str
    rows: int; size_bytes: int

def fetch_manifest(url: str) -> dict
def relevant_slices(manifest: dict, excluded: set[str], conn) -> list[SliceInfo]
def changed_slices(conn, slices: list[SliceInfo]) -> list[SliceInfo]
```

`relevant_slices` takes `conn` (extending the original signature) because it's
the function that detects a malformed manifest and the spec explicitly wants
that logged to the `errors` table (`log_error(stage="poll")`), which needs a
connection. `load_excluded_ats` is small necessary plumbing to load

fetched during implementation): `by_ats` is a **dict** keyed by ATS name, not a
list. Each entry carries **two separate hash/size pairs** — `sha256`/`size_bytes`
for the CSV, `parquet_sha256`/`parquet_size_bytes` for the parquet file — since
we read parquet, `SliceInfo.sha256`/`size_bytes` must come from the `parquet_*`
fields (falling back to the plain ones only when `parquet` itself is absent and
we fall back to CSV). Confirms scope.md's numbers exactly: excluded-source bytes
= 945,818,143 (≈946 MB, matching §3.1's estimate), `meta` is genuinely the
zero-row example, and all 65 ATS entries currently have a `parquet` key. Also
observed: `generated_at` was `2026-08-07`, i.e. **12 days stale** as of this
build — real evidence for §2's "freshness cadence is unknown" caution.

**Logic:**
- Read `by_ats` from the manifest.
- Drop the 15 excluded sources from `config/excluded_ats.json`
  (scope.md §3.1). Log the excluded count and total bytes skipped at `INFO`.
- Skip any slice with `rows == 0` (e.g. `meta` is empty) — log at `DEBUG`.
- Prefer `parquet` URL; only fall back to `csv` if parquet is absent.
- Compare each `sha256` against `slice_state`. Return only changed/new.
- Log `INFO`: `"N/M slices changed, X MB to download"`.
- If **zero** slices changed → return `[]`; caller exits early. This is the
  expected case for most of the 48 daily polls.

**Error handling:** network failure / malformed manifest / missing `by_ats`
→ `log_error(stage="poll")`, return `[]`. A bad manifest must not crash the run.

**Tests:**
- All 15 excluded sources are filtered out (assert on names, not just count).
- Zero-row slices skipped.
- Unchanged sha256 → not returned.
- Changed sha256 → returned.
- Malformed manifest → `[]` + error row.
- Missing `parquet` key → falls back to `csv`.

## Module 6 — Slice Fetcher

**File:** `src/coldstart/fetcher.py`

**Responsibility:** Download changed slices to local parquet and load as DataFrames.

**Interface:**
```python
RAWJOB_COLUMNS: list[str]   # physical parquet columns to request — see note below

def download_slice(slice_info: SliceInfo, data_dir: Path, conn) -> Path
def load_slice(path: Path, columns: list[str]) -> pd.DataFrame
def verify_sha256(path: Path, expected: str) -> bool
```
`download_slice` takes `conn` (extending the original signature, same reason
as Module 5's `relevant_slices`) so a download that fails after retries can
`log_error(stage="poll")` before raising `DownloadError` for the caller to
catch and skip.

**Real schema check (downloaded and inspected 3 live slices — apple, lever,
greenhouse — during implementation):** the actual parquet columns are `url,
title, company, ats_type, ats_id, location, country_iso, region, language,
lat, lon, is_remote, salary_min, salary_max, salary_currency, salary_period,
salary_summary, employment_type, department, team, description, posted_at,
requisition_id, apply_url, commitment, raw`. Two things `RawJob` (Module 4)
assumes **do not exist as columns**:
- **`global_id`** — there is no such column anywhere. `ats_id` exists but is
  only unique *within* one `ats_type` (and its dtype even varies — int64 for
  apple/greenhouse, `str` for lever). `load_slice` synthesizes
  `global_id = f"{ats_type}:{ats_id}"` after reading, which is exactly what
  scope.md §4.4's "`global_id` (or `url` if absent)" phrasing was already
  hedging against — it just turns out `global_id` is *never* present, not
  occasionally.
- **`experience`** — no such column exists at all, in any slice. scope.md
  §6.4 already treats `experience` as "commonly `None`"; in reality it's
  *always* `None` from the source data (the LLM-estimate-from-JD-prose path
  is therefore the only path that ever fires, not a fallback for rare
  cases). `load_slice` sets it to `None` for every row.

`RAWJOB_COLUMNS` is therefore the 13 *physical* columns needed to build a
`RawJob` (`url, requisition_id, company, title, location, country_iso,
is_remote, apply_url, ats_type, posted_at, description, raw, ats_id`) —
`ats_id` is requested transiently for the `global_id` synthesis and dropped
afterward, so `load_slice`'s returned DataFrame ends up with exactly
`RawJob`'s 14 fields. Also note: `raw` is a **JSON-encoded string** in the
parquet, not a dict — left as a string in the DataFrame; parsing it happens
wherever a row becomes a `RawJob` (not this module's concern). And
`country_iso` uses `''` (empty string) for unknown, not null — worth
remembering when Module 7 (Location Filter) is built.

**Requirements:**
- **Stream to disk** (`httpx.stream`, chunked) — never `response.content`
  into memory. Some slices are hundreds of MB.
- Verify sha256 after download; on mismatch, delete the file, retry once,
  then `log_error` and skip that slice.
- **Column projection is mandatory** — read only the columns in
  `RawJob` via `pd.read_parquet(path, columns=[...])`. This is the single
  biggest memory lever; `description` is large and we only need it transiently.
- Cache downloaded files in `data_dir`; skip re-download if the file exists
  and its sha256 matches.
- Log per slice at `INFO`: name, MB, seconds, row count.
- Use `tenacity`: 3 attempts, exponential backoff, retry on
  `httpx.HTTPError` / timeout only.

**Error handling:** any slice that fails after retries → `log_error(stage="poll")`,
skipped, **pipeline continues with the other slices**. One bad slice must not
abort the run.

**Tests:**
- sha256 mismatch → retries then skips, error logged.
- Column projection: loaded DataFrame has exactly the requested columns.
- Existing valid cached file → no re-download (assert no HTTP call).
- HTTP 500 → retried per tenacity config.
- Streaming: assert peak memory stays bounded (mock a large body).

**Done when:** a changed slice lands on disk, verifies, and loads with only projected columns.

## Module 7 — Location Filter ("god mode")

**File:** `src/coldstart/filters/location.py`

**Responsibility:** Classify each job as US / not-US / uncertain. Nothing else.

**Interface:**
```python
def classify_location(
    location: str | None, country_iso: str | None, is_remote: bool | None
) -> tuple[LocationFlag, str]     # (flag, reason)

def filter_locations(df: pd.DataFrame) -> pd.DataFrame  # adds location_flag, location_reason
```

**Cascade (exact order — scope.md §4.1):**
1. `country_iso == "US"` → `ACCEPTED`, reason `"country_iso"`.
   Any other non-null `country_iso` → `REJECTED`, reason `"country_iso_foreign"`.
2. **Non-US country veto** — scan for explicit foreign country//city markers
   (`Canada`, `India`, `United Kingdom`, `Germany`, `Toronto`, `Bangalore`,
   `London`, …). If matched **and** no US state/marker also matched →
   `REJECTED`. This must run **before** state matching so `"Ontario, CA"`
   (Canada) and `"London, ON"` don't false-positive.
3. US country-level markers, word-boundary regex: `\bUS\b`, `\bU\.S\.\b`,
   `\bUSA\b`, `\bU\.S\.A\.\b`, `\bUnited States\b`, `\bUS-Remote\b`,
   `\bRemote\s*[-—–,(]?\s*US`, `\bNorth America\b` (the last only when
   `is_remote` is true) → `ACCEPTED`.
4. State lexicon from `config/us_states.json`, **word-boundary anchored**:
   full names (`California`) and 2-letter abbreviations (`CA`). Abbreviations
   must match only as standalone tokens, typically after a comma —
   `r"(?:,\s*|\b)" + abbr + r"\b"`. **Known collision words that must not
   match as abbreviations in prose:** `OR`, `IN`, `ME`, `OK`, `HI`, `PA`,
   `DE`, `LA`, `MA`, `AL`, `AR`, `MS`, `MT`, `MD`, `MN`, `MO`, `SC`, `WA`.
   For these, require the comma-preceded form or an accompanying US signal.
5. City→state table from `config/us_cities.json` (top ~150 US metros) for
   city-only strings like `"Los Angeles"`, `"NYC"`, `"SF"`, `"Bay Area"`.
6. Bare `"Remote"` with no country signal → `UNCERTAIN` (a global-remote
   posting may or may not be US-eligible).
7. Null/empty location and null `country_iso` → `UNCERTAIN`.
8. Anything unresolved → `UNCERTAIN`. **Never `REJECTED` by default.**

**Config files to author:** `us_states.json` (50 states + DC + PR),
`us_cities.json` (metro → state), and a foreign-marker list.

**Logging:** `INFO` summary counts per flag. `DEBUG` per-job decision with
reason. `WARNING` if `UNCERTAIN` exceeds 15% of a batch (signals a lexicon gap).

**Tests (`tests/test_location.py`) — drive from `fixtures/locations.json`, each case `{input, expected_flag, note}`:**

| Input | Expected |
|---|---|
| `"Los Angeles, CA"` | ACCEPTED |
| `"California"` | ACCEPTED |
| `"United States"` | ACCEPTED |
| `"Remote — US"` / `"Remote (USA)"` / `"US-Remote"` | ACCEPTED |
| `"Los Angeles"` (city only) | ACCEPTED (city table) |
| `"NYC"` / `"SF"` / `"Bay Area"` | ACCEPTED |
| `"Austin, TX or Remote"` | ACCEPTED |
| `"Ontario, CA"` (Canada) | REJECTED |
| `"London, ON"` | REJECTED |
| `"Toronto, Canada"` | REJECTED |
| `"Bangalore, India"` | REJECTED |
| `"Berlin, Germany"` | REJECTED |
| `"Remote"` (bare) | UNCERTAIN |
| `None` / `""` | UNCERTAIN |
| `"Remote - North America"` + `is_remote=True` | ACCEPTED |
| `"Portland, OR"` | ACCEPTED |
| `"Work in a team OR independently"` (prose w/ `OR`) | not ACCEPTED via `OR` |
| `"Located in Maine"` | ACCEPTED |
| `"Indiana"` vs `"located in India"` | ACCEPTED / REJECTED |
| `country_iso="DE"`, location `"California St, Berlin"` | REJECTED (step 1 wins) |

**Real-data finding — `country_iso="CA"` is unreliable, not a hard signal.**
Verified live: `country_iso` is empty (`""`) for 63–88% of rows across
greenhouse/lever/ashby/workday, so treating empty as "absent" (not foreign)
is essential, not an edge case. More importantly, on a real greenhouse slice
(181k rows), `country_iso="CA"` was the **second most common non-empty
value** (11,634 rows) — and it's genuinely ambiguous: `CA` is the real
ISO-3166 code for **Canada**, but it also turned out to be a frequent
data-quality bug where **California** ends up in `country_iso` instead of
`US`. Sampling the actual locations: `San Francisco, CA` (1,011 rows),
`Los Angeles, CA` (767), `Hawthorne, CA` (607)... vs. genuine Canada like
`Toronto, Ontario, Canada` (357), `Canada` (289) — California outnumbered
real Canada roughly 2:1. Trusting `country_iso` outright at step 1 (as
originally spec'd — "best signal, use first") would have **silently
rejected thousands of legitimate California jobs**, exactly the failure
mode §10's "never silently drop" principle exists to prevent.

Checked whether this generalizes to other state/country abbreviation
collisions (`DE`=Delaware/Germany, `IN`=Indiana/India, `PA`=Pennsylvania/
Panama, `MT`=Montana/Malta, `MD`=Maryland/Moldova, `MO`=Missouri/Macao,
`SC`=South Carolina/Seychelles) — only `DE` appeared at meaningful volume
(2,580 rows), and every sampled row was genuinely Germany (`Berlin,
Germany`, `Munich, Germany`), never Delaware. So the fix is narrow and
evidence-based: **only `country_iso="CA"` is treated as unreliable** and
deferred to the location-text cascade (steps 2+) rather than trusted as
Canada outright; every other non-US `country_iso` value keeps the original
"hard reject at step 1" behavior. Re-running the filter on the same
greenhouse slice after the fix: accepted jobs rose from 103,760 to 112,196
(+8,436), with genuine Canadian postings still correctly rejected.

**Done when:** every fixture case passes and coverage on `location.py` is ≥95%.

## Module 10 — Deduplication

**File:** `src/coldstart/dedupe.py`

**Responsibility:** Drop already-seen jobs, in memory.

**Interface:**
```python
ReqKey = tuple[str, str, str]   # (company, requisition_id, location) — see note below

def dedupe(df: pd.DataFrame, seen_global: set[str], seen_req: set[ReqKey]) -> pd.DataFrame
```

**Real-data finding — bare `requisition_id` is not a safe dedup key, not even
per-company.** The original design (scope.md §4.4) treats `requisition_id` as
"the employer's internal id" and dedupes on it directly. Tested against a
real 181k-row greenhouse slice and this breaks badly at two levels:
- **Globally**, `requisition_id` values collide constantly across
  *different* companies — `requisition_id="1"` alone was shared by 4,509
  completely unrelated postings (different companies, titles, locations),
  because many small companies independently start their own internal
  numbering at 1.
- **Even scoped to `(company, requisition_id)`**, it still breaks: one
  company (`svetness`) had 4,382 genuinely different job openings — same
  title ("Personal Trainer"), but posted separately for dozens of different
  cities (Tyler TX, Troy TX, Tioga TX, ...) — all sharing `requisition_id="1"`
  as an apparent placeholder/default value their posting workflow never
  varies.

Collapsing either of these down to one row per the original design would
have **silently discarded thousands of genuinely distinct job postings** —
exactly the "never silently drop" failure the whole project is designed to
avoid. Fix: the dedup key is **`(company, requisition_id, location)`**, not
bare `requisition_id`. A job genuinely mirrored across two ATS platforms
(the actual scenario this mechanism exists for) shares company,
requisition_id, *and* location, since it's describing the same real-world
opening — so this doesn't break the intended use case, it just adds the one
extra field needed to stop conflating same-title-different-city postings
that happen to share a reused/default requisition_id. Minor location-string
inconsistencies (whitespace, phrasing) can only cause *under*-matching (a
near-duplicate slips through), never over-matching (a real opportunity
silently lost) — the safer failure direction here.

This changes Module 3's `load_seen_keys` return type too: the second set is
now `set[tuple[str, str, str]]` (company, requisition_id, location) instead
of `set[str]`, and the `jobs` table query underlying it selects all three
columns. `db.py`/`test_db.py` are updated accordingly.

**Logic (scope.md §4.4, revised per the finding above):**
- Load seen keys **once per run** via `db.load_seen_keys` — one query, not per row.
- Drop rows whose `global_id` is in `seen_global`.
- Then drop rows whose non-null `(company, requisition_id, location)` is in
  `seen_req` (same real job mirrored across ATSes).
- Also dedupe **within** the current batch on `(company, requisition_id,
  location)` (keep the first occurrence, prefer the row with a non-null
  `posted_at`).
- Log `INFO`: `"in=N, seen_global=A, seen_req=B, intra_batch=C, out=D"`.

**Tests:**
- Known `global_id` dropped.
- Known `(company, requisition_id, location)`, new `global_id` → dropped.
- Null `requisition_id` never collides with another null.
- Same `requisition_id`, different `company` → NOT collapsed (the "1" collision case).
- Same `company` + `requisition_id`, different `location` → NOT collapsed (the "svetness" case).
- Intra-batch duplicate collapsed to one row.
- Empty seen sets → nothing dropped.

**Done when:** running the same slice twice yields zero new jobs on the second pass.

## Module 15 — Scorer / Orchestration

**File:** `src/coldstart/scoring/scorer.py`

**Responsibility:** Score jobs with retry, validation, and provider failover.

```python
def score_job(job: RawJob, resume_text: str, chain: list[LLMProvider], conn, settings) -> JobScore | None
def score_jobs(jobs: list[RawJob], ..., batch_size: int = 1) -> list[tuple[RawJob, JobScore | None]]
```

**Flow per job (scope.md §6.3):**
1. Budget check (M16) — if the ceiling is hit, stop the whole run (`CRITICAL`).
2. For each provider in the chain:
   - Up to `max_retries_per_provider` attempts, exponential backoff
     (`tenacity`), retrying only `RateLimitError` / `ProviderUnavailable`.
   - Parse response → strip markdown fences if present → `json.loads` →
     `JobScore.model_validate`.
   - On `ValidationError` / JSON error: **one** correction retry appending
     `"Your previous response did not match the required JSON schema. Return only valid JSON matching: {schema}"`.
   - On success: record spend (M16), return.
   - On provider exhaustion: `log_error(stage="llm_score", provider=...)`,
     move to the next provider.
3. All providers exhausted → return `None`; caller persists the job with
   `status=FAILED`. **The job is never dropped.**
4. `batch_size` from settings; default 1. Implement the batched path
   (N jobs per call, list-of-objects response) but keep 1 the default so
   flipping the env var is the only change needed later.

**Logging:** `INFO` per job: provider, model, score, band, latency, tokens
(with cache hit ratio). `WARNING` on schema-correction retry and on failover.
`ERROR` on provider exhaustion. `INFO` run summary: scored / failed / by band.

**Tests:**
- Happy path with `FakeProvider`.
- Malformed JSON → one correction retry → success.
- Malformed twice → `None` + error row + `status=FAILED`.
- 429 on provider 1 → fails over to provider 2 → success (assert both called).
- All providers 429 → `None` + error row.
- Markdown-fenced JSON is parsed.
- `eligible=False` from the LLM → score forced to 0 (model validator).
- Budget exceeded → run stops, `CRITICAL` logged.
- `batch_size=2` returns two results in order.

**Done when:** no input — malformed, rate-limited, or empty — can lose a job without a `FAILED` row and an error entry.

## Module 19 — Pipeline Orchestrator

**Files:** `src/coldstart/pipeline.py`, `scripts/run_poll.py`, `scripts/run_digest.py`

**Responsibility:** Wire the modules. No business logic of its own.

```python
def run_poll(settings) -> PollResult
def run_digest(settings) -> bool
```

**`run_poll` sequence:**
```
run_id = new_run_id(); setup_logging(...)
settings = load_settings()                 # fail fast
with connection(db) as conn:
    init_schema(conn)
    if not check_resumes_ready(resumes_dir, settings.resume_manifest):
        ingest_resumes(resumes_dir, settings.resume_manifest, chain, conn)  # raises ResumesNotReady -> CRITICAL, exit
    manifest = fetch_manifest(...)
    slices   = changed_slices(conn, relevant_slices(manifest, excluded))
    if not slices: log INFO "no changes"; return early     # the common case
    seen_global, seen_req = load_seen_keys(conn)
    for slice in slices:                    # one slice at a time — memory
        path = download_slice(...); df = load_slice(path, columns=RAWJOB_COLUMNS)
        df = filter_titles(df)              # cheapest, most decisive first
        df = filter_locations(df)
        df = df[df.location_flag != REJECTED]
        df = filter_eligibility(df)
        # persist EXCLUDED rows immediately, then drop them
        df = dedupe(df, seen_global, seen_req)
        for job in df.itertuples():         # small set by now
            resume_id, method = route(job, manifest, provider)
            score = score_job(job, resume_text[resume_id], chain, conn, settings)
            upsert_job(conn, to_record(job, score, ...))   # commit per job
            seen_global.add(job.global_id)                 # keep sets current across
            if job.requisition_id:                         # slices within this run, not
                seen_req.add((job.company, job.requisition_id, job.location))  # just across runs
        set_slice_state(conn, ...)           # only after the slice fully processes
        del df; gc.collect()
    export_csv(...)
```

**Requirements:**
- **Resume readiness is checked before anything else runs** — `run_poll`
  aborts immediately (before the manifest poll) if the 4-slot resume set
  can't be resolved (M2.5). Fail fast, before spending any network or LLM budget.
- **Filter order is fixed:** title → location → eligibility → dedupe → route
  → score. Cheapest and most decisive first; LLM last.
- **Process one slice at a time**, freeing the DataFrame before the next —
  never hold several hundred-MB frames simultaneously.
- Update `slice_state` **only after** a slice completes, so a crash mid-slice
  causes a safe re-process rather than silently skipping data.
- Persist `EXCLUDED` and `UNCERTAIN` jobs — they are results, not discards.
- Wrap each stage in `@capture_errors(stage=...)`; a single slice failure must
  not abort the run.
- `run_digest` is a **separate entrypoint** (different cron schedule) reading
  from the DB — it never re-scores.

**Tests (integration, `tests/test_pipeline.py`):**
- End-to-end on `fixtures/sample_jobs.parquet` with `FakeProvider`: assert
  correct counts by status/band, CSV written, `slice_state` updated.
- No changed slices → early return, zero LLM calls.
- Mid-slice crash → `slice_state` unchanged → re-run reprocesses.
- One slice fails to download → others still process.
- Idempotency: second identical run scores zero new jobs.
- Every fixture job ends in exactly one terminal status (the core invariant).

**Done when:** a full run over fixtures produces the expected DB state, CSV, and digest with zero unhandled exceptions.
